# AI Model Documentation

This project keeps the original delay-regression model and adds three additional models for railway operational analysis.

## Model 1: Delay regression

- Purpose: estimate predicted delay minutes for a train movement request.
- Dataset: synthetic railway-delay data generated by `ml/generate_dataset.py`.
- Target: `delay_minutes`.
- Artifact: `ai-service/artifacts/delay_model.joblib`.
- API: POST `/predict/delay`.
- Training command:
  ```bash
  cd ai-service
  python ml/train_delay_model.py --dataset data/delay_dataset.csv --output artifacts/delay_model.joblib --metadata-output artifacts/delay_model_metadata.json
  ```
- Held-out metrics: MAE 3.06, RMSE 3.84, R2 0.87.
- Limitation: synthetic data only; it does not claim real-world railway accuracy.

## Model 2: Delay severity classification

- Purpose: assign a qualitative delay category (`minor`, `moderate`, `major`, `severe`).
- Dataset: the same synthetic delay dataset with the delay minutes converted into severity thresholds.
- Target: category based on `minor < 10`, `moderate < 25`, `major < 45`, otherwise `severe`.
- Artifact: `ai-service/artifacts/delay_classification_model.joblib`.
- API: POST `/predict/delay-classification`.
- Training command:
  ```bash
  cd ai-service
  python ml/train_delay_classification_model.py --dataset data/delay_dataset.csv --output artifacts/delay_classification_model.joblib --metadata-output artifacts/delay_classification_model_metadata.json
  ```
- Held-out metrics: accuracy 0.87, precision 0.87, recall 0.87, F1 0.87.
- Limitation: severity thresholds are configurable but still derived from synthetic data.

## Model 3: Congestion prediction

- Purpose: estimate a track or route congestion level from queueing and timing features.
- Dataset: synthetic simulation-style data generated from train density, occupancy, pending requests, and availability.
- Target: ordinal `congestion_level` in {0, 1, 2, 3, 4}.
- Artifact: `ai-service/artifacts/congestion_model.joblib`.
- API: POST `/predict/congestion`.
- Training command:
  ```bash
  cd ai-service
  python ml/train_congestion_model.py --dataset data/congestion_dataset.csv --output artifacts/congestion_model.joblib --metadata-output artifacts/congestion_model_metadata.json
  ```
- Held-out metrics: accuracy 0.88, precision 0.88, recall 0.88, F1 0.88.
- Limitation: the labels are generated from a realistic internal simulation heuristic and should be treated as operational guidance, not real-world congestion truth.

## Model 4: Anomaly detection

- Purpose: flag unusual operational conditions that differ from normal queueing behavior.
- Dataset: synthetic normal-operation data with deliberately abnormal occupancy and queueing patterns.
- Target: binary anomaly flag (`0` normal, `1` anomaly).
- Artifact: `ai-service/artifacts/anomaly_model.joblib`.
- API: POST `/predict/anomaly`.
- Training command:
  ```bash
  cd ai-service
  python ml/train_anomaly_model.py --dataset data/anomaly_dataset.csv --output artifacts/anomaly_model.joblib --metadata-output artifacts/anomaly_model_metadata.json
  ```
- Held-out metrics: accuracy 0.99, precision 0.95, recall 0.96, F1 0.96.
- Limitation: anomaly scores identify unusual patterns, not the root cause of an incident.

## Notes

- All artifacts are stored under `ai-service/artifacts/`.
- The service loads model artifacts explicitly and fails with HTTP 503 when a required artifact is missing or invalid.
- Synthetic-data performance is reported honestly; it does not imply real-world railway accuracy.
